## 2. Architecture

### 2.1 Packages and `l10n.yaml`

`flutter_localizations` (SDK) is added; `intl` is already a dependency
(`^0.20.3`, used for the monthly equivalent). `pubspec.yaml` gets
`flutter: generate: true`. On this Flutter (3.44.6) gen-l10n writes the
generated code into the project, not a synthetic package, so the output
folder is chosen explicitly:

```yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-dir: lib/l10n/generated
output-localization-file: app_localizations.dart
output-class: AppLocalizations
nullable-getter: false
required-resource-attributes: true
untranslated-messages-file: build/l10n/untranslated.json
```

`required-resource-attributes` forces a `@key` description on every entry,
which is what the AI translation step (B5) reads for context. The
untranslated-messages file is B5's completeness check. The generated
folder is regenerated by every Flutter command that resolves the project
(`pub get`, `run`, `build`, `test`), so it is not committed (`.gitignore`
entry; §8 Q6). The `dart format` rule in the owner's notes (pub get first)
is unchanged.

### 2.2 ARB layout and keys

One file per locale in `lib/l10n/`: `app_en.arb` (template), `app_ja.arb`,
`app_ko.arb`, `app_es.arb`, `app_pt.arb`, `app_tr.arb`, `app_ar.arb`,
`app_de.arb`. In B3 only `app_en.arb` has content; the seven others are
created empty in B5's first commit, not before (an empty ARB makes gen-l10n
emit English fallbacks and warnings for every key).

**Brazilian Portuguese:** gen-l10n requires a base-language file for every
regional file (`app_pt_BR.arb` without `app_pt.arb` is an error), and a
device set to European Portuguese would otherwise fall back to English.
Proposal: one `app_pt.arb` holding the Brazilian text, declared as the
locale `pt`; the analytics value stays `pt-BR` as the plan states (§6, §8
Q1).

**Key naming:** gen-l10n keys must be Dart identifiers, so "screen.purpose"
is written as a camelCase prefix: `homeGreetingMorning`,
`settingsThemeLabel`, `paywallAnnualSavings`, `questionHintSlideLabel`,
`commonRetry`, `commonCancel`, `featureDailyTest`. Prefix = the screen or
the shared widget that owns the string; `common*` for the few shared
verbs; `feature*` for the five names. Placeholders are typed in the
metadata (`{count}` int, `{name}` String, `{price}` String) and plurals use
ICU syntax.

### 2.3 `context.l10n`

`lib/l10n/l10n.dart` exports the generated class and one extension:

```dart
extension AppLocalizationsX on BuildContext {
  AppLocalizations get l10n => AppLocalizations.of(this);
}
```

The same file holds `AppLanguage`: an enum of `system` plus the eight
languages, each with its `Locale`, its endonym for the picker ("English",
"日本語", "한국어", "Español", "Português (Brasil)", "Türkçe", "العربية",
"Deutsch"; endonyms are constants, not ARB entries, since they are never
translated), its stored value and its analytics value (`en`, `ja`, `ko`,
`es`, `pt-BR`, `tr`, `ar`, `de`). `AppLanguage.supportedLocales` lists
English first, which is also how `MaterialApp` picks the fallback.

### 2.4 Where the language is chosen and stored

- **Storage:** a `language_settings (id, language TEXT)` row, the pattern
  of `theme_settings` and `text_size_settings`, schema v26 (`CREATE TABLE
  IF NOT EXISTS` in `onCreate` and in `onUpgrade`); `getLanguage()` returns
  `AppLanguage.system` for no row or an unknown value.
- **State:** `_GrammarLensAppState` holds `_language`, loaded in `initState`
  beside `_loadTextSize` and reset by the debug "Reset local data", set by
  `_setLanguage` (setState, persist, user property), and handed to
  `SettingsScreen` as `language` / `onSelectLanguage` like the text size.
- **Settings row:** in the Appearance card, under Text size, a navigation
  row "Language" with the current choice as its value ("System default" or
  the endonym). Eight options are too many for the segmented button the
  two other settings use, so the row opens a small picker screen: a radio
  list, "System default" first with the resolved language under it, then
  the eight endonyms. Changing the selection applies at once and pops.
  (§8 Q3.)
- **No language step in onboarding:** the system language is resolved
  before the first frame, so a Japanese device starts in Japanese; the
  Profile row is for overriding it.

### 2.5 Resolving the system locale

`MaterialApp` gets `supportedLocales`, the four delegates
(`AppLocalizations.delegate`, `GlobalMaterialLocalizations`,
`GlobalWidgetsLocalizations`, `GlobalCupertinoLocalizations`), `locale:
_language.locale` (null while on System) and a
`localeListResolutionCallback` that calls one pure function,
`resolveAppLocale(List<Locale>? preferred)`: walk the device's preferred
list in order; the first whose `languageCode` is one of the eight wins,
country and script ignored (`pt-PT` → pt, `es-MX` → es, `ar-EG` → ar,
`zh` and `ru` are skipped); none → `en`. Unit-tested on those cases. With
an explicit `locale`, Flutter bypasses the callback, so a chosen language
always wins. The same function is called from the app state (on the
platform's `locales` at startup and in `didChangeLocales`, which the
existing `WidgetsBindingObserver` mixin receives) to know the *resolved*
language for `ui_language` (§6).

### 2.6 A language change at runtime

`_setLanguage` calls `setState` at the root; `MaterialApp` rebuilds with the
new `locale`, the `Localizations` widget below it changes, and every widget
that read `context.l10n` in `build` rebuilds through the inherited
dependency. `TabSwitcher` keeps the three tabs' `State` objects alive,
which is fine as long as strings are read in `build`. What B4 must watch
for while moving strings: labels computed once in `initState` or stored in
`late final` fields, the `const _navTabs` list in `app.dart` (becomes a
function of context), SnackBars already on screen (they stay in the old
language and go away), and the `TextPainter` measurement that lays out
from an English literal (`_themeIconsFit` measures the word "System" to
decide whether the theme segments get icons): it must measure the
localised label, and the longest of the three, since "System" is not the
widest segment in every language. Text direction flips with
the locale on its own (`GlobalWidgetsLocalizations` reports RTL for `ar`),
which is why §3 prepares the layout now.

Text size, theme and language are three independent root settings; the
first frame after launch uses the system locale until the stored choice
loads, the same millisecond-scale race the theme and text size have today.
It is covered by the launch splash (`LaunchGate` draws over the first
frames), and `_loadLanguage` runs in `initState` with the other loads, so
no extra gate is added.

### 2.7 Launch screen and iOS project

- **Launch screen:** the storyboard draws `LaunchImage` only, the Flutter
  splash draws the logo and the brand wordmark: nothing to localise. The
  "Loading…" line under the splash becomes an ARB string.
- **`Info.plist`:** add `CFBundleLocalizations` with `en`, `ja`, `ko`, `es`,
  `pt-BR`, `tr`, `ar`, `de`. This is what the App Store page lists under
  Languages and what makes iOS offer a per-app language under Settings →
  GrammarLens; the per-app choice arrives as the device's first preferred
  locale, so "System default" follows it. `CFBundleDevelopmentRegion`
  stays `en`. No `.lproj` folders or `InfoPlist.strings` are needed: the
  plist has no usage descriptions, and the display name is the brand.
- **Xcode `knownRegions`** gets the eight languages (cosmetic for Flutter,
  but it keeps Xcode's Localizations panel truthful).
- **Android:** no release track; nothing is done.
- **Fonts (noted for B5/B6, nothing in B3):** Nunito Sans covers the Latin
  languages (tr, de, es, pt) but has no Japanese, Korean or Arabic glyphs;
  iOS falls back to its system fonts for those. `withWeight` sets both
  `fontWeight` and the `wght` variation, so the fallback fonts keep the
  intended weight.

## 4. B4 batching plan and the guard test

### 4.1 The guard test (added in B3, before any string moves)

`test/l10n_guard_test.dart`, modelled on `font_weight_guard_test.dart`: a
lexical scan of every `lib/**/*.dart` outside `lib/l10n/`, the debug and
preview files, `day_zero_daily_test.dart` and `fallback_pool.dart`. A line
offends when it holds a **prose literal**: a string literal with a letter,
a space and another letter (or ending in "…", "." or "?"), not inside
`debugPrint`, `assert`, `throw`, an SQL statement or an analytics name,
and not on a line marked `// l10n-guard: <reason>` (the brand name, enum
wire values, regular expressions). The test carries a **pending list** of
files, every file with a hit today, and fails on a hit in any file not on
the list. B3 ships it with the full list, so no new hard-coded string can
be added from then on; each B4 batch deletes its files from the list, and
B4's last batch deletes the list. Over-matching is handled per line with
the marker, under-matching is accepted: the test is a tripwire, not a
proof.

A second guard arrives with B5: every locale file has every key of
`app_en.arb` (the untranslated-messages file is empty), the `feature*`
values equal English in every locale, and each key's placeholders match
the template's.

## 5. Keyboard folding, client half

### 5.1 The fixture and the proxy's rule (verified)

The shared fixture is `proxy/test/fixtures/keyboard_folding.json` (43
cases; the prompt's `proxy/eval/data/` path holds the measurement data,
not this file). Its header says the proxy test reads it now and the Dart
test reads it from B3. The proxy's `foldKeyboardVariants`
(`proxy/src/shared_daily_test.ts`) is: map every code point through a
closed table (dotless ı; the precomposed Latin letters with a diacritic,
`ß` → `ss`, `æ` → `ae`, `œ` → `oe`; four apostrophe look-alikes and six
quotation marks → `'` / `"`; six dashes → `-`; the Arabic comma and
question mark and the ideographic full stop; `¿ ¡` removed; non-breaking
and ideographic spaces → space; zero-width characters, direction marks and
the BOM removed) plus three ranges by arithmetic (full-width ASCII
U+FF01–FF5E → U+0021–007E; Arabic-Indic U+0660–0669 and Eastern
Arabic-Indic U+06F0–06F9 → ASCII digits); then collapse doubled spaces and
trim; then, **only if the input ended with a full-width or Arabic mark**
(U+3002, U+FF0E, U+FF01, U+FF1F, U+061F), drop one trailing `.`, `!` or
`?`. The result can be shorter or longer than the input. Inputs are
already normalised (`normalizeAnswer`).

### 5.2 Dart implementation

In `lib/utils/answer_matching.dart`, replacing the six-letter table:

- The same table as a `const Map<String, String>`, the same three ranges in
  a `_foldCharacter(int rune)` function, and `foldKeyboardVariants` iterating
  `input.runes` (the proxy's `Array.from` iterates code points; Dart's
  `split('')` would split surrogate pairs), joining, collapsing runs of
  spaces, trimming, and applying the trailing-mark rule on the *input*.
  The comments stop saying "Turkish keyboard" and point at the fixture and
  the eight classes.
- `_keyboardVariantNote` stops pairing characters by index (the fold can
  change length: `ß`, removed marks). New rule, as the server report §2.2
  said: name the characters of the learner's normalised answer whose fold
  differs from themselves, in order, once each, with what they fold to.
  Proposed wording: `You typed "ı", "ş" — your keyboard's versions of "i",
  "s". Not a grammar mistake.`; when a character folds to nothing (`¿`, a
  zero-width mark): `Your keyboard added "¿" — not a grammar mistake.`; both
  clauses when both happen. It is one sentence per clause, so B9's
  formatter still gives three paragraphs on the composed card. (§8 Q8.)
- `AnswerMatchKind.keyboardVariant`'s doc comment and the Daily Test test
  group drop the Turkish list.

### 5.3 Where it is applied, and the proxy's expectation

Exactly where it is today and nowhere new: `checkDailyTestAnswer`'s
keyboard-variant branch against the key and the folded pass over the
accepted alternatives (Daily Test local matching, day-0 and pool
included). Not in the B8 blank guard (it runs on the raw wire answer), not
in "You wrote", not in the stored answers.

**Not before the scorer request.** `scoreAnswers` sends `userAnswer` raw
and the proxy's `/v1/score-answers` path does not fold (`validation.ts`,
`index.ts`, `score_feedback.ts` and `anthropic.ts` do not import the
function; only the shared-set gate, the check module and the pool converter
do). The proxy expects the learner's text as typed: the D3 scoring prompt's
keyboard paragraph is what makes the model tolerate variants (the
measurement showed this paragraph carries the S-synth cells), and the
feedback and the "You wrote" box must show what was actually typed.

## 6. The `ui_language` user property

- **Value:** the language the interface is actually shown in, from the
  closed set `en`, `ja`, `ko`, `es`, `pt-BR`, `tr`, `ar`, `de`
  (`analytics-plan.md` §3; the `pt` locale reports `pt-BR`; values ≤ 5
  characters; 4 user properties in total, under the 25 limit). On "System
  default" it is the resolved language (a Japanese device reports `ja`), not
  the word "system": D2's review compares practice completion by the
  language people read, whichever way they got it.
- **Set:** mirrors `setTextSizeProperty`. (1) At startup, once the stored
  choice has loaded and the platform locales are resolved (`_loadLanguage`),
  so a changed device language is corrected on the next launch; (2) on
  every change in Settings (`_setLanguage`); (3) in `didChangeLocales`
  while on System default. Each call is `AnalyticsService.setUiLanguageProperty(
  AppLanguage resolved)` through the existing best-effort
  `_setUserProperty`, with the param-set test in `analytics_service_test.dart`
  extended.
- **No event and no "how it was chosen":** the property alone answers the
  review's question; an override count can be read later from the
  property's distribution against the device-language dimension Firebase
  already has. (§8 Q4.)
- **Privacy:** a fixed vocabulary, allowed by §4 of the analytics plan.
- **Owner, before the 1.4.0 release:** register `ui_language` as a
  **user-scoped custom dimension** (Firebase console → Admin → Custom
  definitions → Create custom dimension → scope User → user property
  `ui_language`, suggested name "Interface language"). Registration is not
  retroactive; events before it carry the property but reports cannot
  break down by it. `analytics-plan.md` §3 and §9 already list it as
  planned; B3 flips them to "implemented, not registered".

## 7. B2: the hint card gives the answer away

### 7.1 The defect

The card is one fixed text per topic. On the Gerund vs. Infinitive card the
first three lines list the governing verbs ("+ -ing: enjoy, avoid, finish,
keep"; "+ to: want, decide, hope, plan"; "Meaning changes: stop, remember,
try"), and a question's governing verb is the one word that decides the
answer. The recorded example (2026-10-16): day-0 question 1, "You should
avoid ___ too much sugar. (eat)": the card says `avoid` takes -ing, the
answer is "eating".

**Correction (B2 build, 2026-11-02): six cards change, not five.** This
count matched exact words only; with the inflections the rule includes,
the pool's "I decided ___ (ask) for a refund" also changes (it listed
"decide" under "+ to", a real give-away), and "Sara wants…" drops "want"
too. The count as first written:

How often: with the rule below over the 40 bundled questions, 5 cards
change (day-0 q1 and the pool's four Gerund vs. Infinitive questions:
"decided to avoid ___ (buy)", "he really enjoys ___ (compete)", "I avoid to
drive to work", "I really enjoy ___ (listen)"); the other four topics' 35
questions are untouched.

### 7.2 Smallest fix (proposed)

**Hide from the card any listed example word that occurs in the question
text, on the three verb-list lines of the Gerund vs. Infinitive card
only.** Concretely:

- `topic_hints.dart` keeps `kTopicHints` verbatim and adds a pure function
  `hintPointsFor(TopicId topic, String questionText)`: for the lines named
  in a small const set (`gerundVsInfinitive` lines 0, 1, 2) it splits the
  text after the colon on ", ", drops every example whose word occurs in
  the question (lower-cased, whole word, including the regular inflections
  `-s`, `-es`, `-ed`, `-d`, `-ing`, the doubled consonant and `-ies` /
  `-ied`, so "avoids", "decided", "stopped", "tries" match), and re-joins.
  A line that loses every example keeps its label alone ("+ -ing"). Every
  other line and every other topic is returned as is.
- `QuestionView` passes `hintPointsFor(topic.id, item.fullText + hint)`
  instead of `kTopicHints[topic.id]`, so the slider's card **and its
  semantics label** (which joins the points) both change; Daily Test and
  Practice alike, since both show the slider and both have the item text.
- The card only gets shorter, so the 375 × 667 fit test still holds.
  Tests: the function on the five bundled cases, an inflection case, a line
  losing all examples, and a card on each of the other four topics'
  day-0 questions unchanged.

**On the recorded example and the five cards:**

| Topic, question | Card today | Card after |
|---|---|---|
| Gerund vs. Infinitive, day-0 q1 "You should avoid ___ too much sugar." | + -ing: enjoy, **avoid**, finish, keep · + to: want, decide, hope, plan · Meaning changes: stop, remember, try · After a preposition: always -ing | + -ing: enjoy, finish, keep · (the other three lines unchanged) |
| Gerund vs. Infinitive, pool "she has decided to avoid ___ expensive coffee" | as above | + -ing: enjoy, finish, keep · + to: want, hope, plan ("decided" matches "decide"; harmless, and the rule stays one rule) · the rest unchanged |
| Modal Verbs, day-0 q3 "She can speaks three languages." | modal + base verb: no "to", no "-s" · must: obligation · should: advice · may / might / could: possibility · mustn't ≠ don't have to | unchanged (no verb-list line) |
| Modal Past Forms, day-0 q4 "Tom said he ___ call me the next day." | modal + have + past participle · must / can't have … · might / could have … · should have … | unchanged |
| Tense Selection, day-0 q5 "Yesterday I ___ a great film." | Past simple: finished time (ago, in 2020) · Present perfect: up to now (since, for, yet) · Past perfect … · Continuous … | unchanged |
| Articles, day-0 q2 "She is best student in our class." | a / an: one of many, or first mention · an before a vowel sound: an hour · the: specific, known, or the only one · No article: general plural or uncountable | unchanged |

**Why only the verb lists.** A whole-word scan of every hint word against
the 35 pool questions matches 21 questions, but almost all through
function or signal words: "the" (Articles, in nearly every sentence),
"since" / "for" / "now" (Tense Selection), "should" / "have" (modals). Those
lines teach the mapping from a signal to a form, which is the hint's
purpose, not the answer; hiding "the" would gut the Articles card. The
verb lists are the one place where the listed word *is* the question's
decisive word. (§8 Q5.)

**Rejected:** a second hint variant per topic (needs new owner text and a
choice rule, and the variant without the verb would still name its
neighbours), hiding the whole line (loses "+ -ing" itself, the useful
part), and matching the answer key instead of the question (on a fill-in
the key is the conjugated verb, which is never on the card; on an error
correction the key is the whole sentence, which adds nothing over the
question text).
